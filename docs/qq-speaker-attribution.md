# 群聊历史发言归属修复

2026-10-27：补齐未 @ 消息、旧记录、摘要和模型接口之间的身份传递。

- 用户消息身份取自本机消息元数据 `name`、`subject`、`sender.qq`，不解析正文内的 QQ 标签或昵称。如果这些有效字段互相冲突，按未知身份处理。
- 群聊记录缺少身份时标记 `qq_unknown`，不推定为本轮发言者。旧私聊缺少身份时可依据其会话号码补回；有冲突时仍标为未知。
- 所有用户历史在完成摘要/裁剪后、请求模型前统一转换为 `[qq_号码] "JSON 转义后的正文"`。当前用户的旧消息也有标记。原文的伪前缀、引号和换行只是字符串内容，不能替代最外层程序标记。
- 压缩摘要保留每条内容的归属标识，身份不明的旧摘要也保留未知标识。共享近期消息中不再把机器人答复的接收者 `subject` 当作机器人消息的作者。
- 新增原文笔记和事实均绑定本轮协议事件里的用户号码。旁听但未触发的消息仍只进入临时上下文，不追加为另一个人的长期事实。
- 原始聊天文字和当前用户输入保持原样；模型输入的展示标记不会写回历史正文。

测试包含伪造前缀、身份冲突、旧记录重启、多用户旁听、压缩摘要，以及 OpenAI 兼容/Anthropic 请求体实际序列化。`desktop/verify-qq-speaker-attribution.mjs` 额外加载测试软件目录中的代码，通过模拟网络与发送验证整个处理链路，不调用外部 API 或真实发送 QQ 消息。

已有事实若早先就被写入了错误的 `who`，且原始来源无法证明真实作者，本次不会猜测并批量修改；可在本机记忆面板核对后更正。此修复保证程序提供明确一致的归属资料，无法保证模型永远不误读。
