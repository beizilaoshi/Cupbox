# Cupbox 原生工作模式

聊天与工作都使用 Cupbox 自己的主页面、输入框、模型菜单、工具调用卡片和历史记录。工作模式不启动 Harness Web 应用，不嵌入 WebContentsView，不打开额外的浏览器或窗口。

## 使用

- 默认聊天，不需要工作文件夹。输入框下方切换“工作模式”才选择目录；取消保留原聊天和草稿。权限与运行设置继续决定本机或沙箱执行，沙箱不会因选择模式而被关闭。
- 直接描述目标后发送，由 AI 选择工具。工具过程实时显示在原生对话中，重要操作使用 Cupbox 的批准弹窗；停止按钮取消当前任务并释放后台内核。
- AI 澄清问题和计划审核使用 Cupbox 原生表单，支持单选、多选和补充文字；计划不会默认批准，停止任务会撤销尚未回答的问题。
- 原有 Cupbox 文件、办公和桌面工具通过适配器接入同一个执行循环，继续经过原有执行器和授权检查。文件工具开关、Agent 预设、私有数据保护均在后台生效。
- 文件读取、编辑、任务清单、目标、技能、后台任务、子任务等由 SDK 配置实际启用的内核能力提供；工具箱的 70 项目录仍是接口参考，含需要额外配置及上游未发布的接口，不能将清单数量当成已启用数量。
- 普通聊天记录直接打开续聊。工作记录同时保留 Cupbox 对话和内核会话标识，再次发送恢复原任务上下文；期间的普通聊天会作为新增背景同步。
- 清空或删除 Cupbox 条目会断开对应内核记录并从旧任务列表隐藏，避免清空后再次带入原有上下文。原始运行日志保留其持久化格式。
- 旧版 Harness 任务从“最近任务”打开时读取原始日志，转换为 Cupbox 本地对话并建立关联，不请求模型、不修改原始会话文件；之后在原生界面继续。

## 内核适配

`harness-engine.js` 通过 SDK 的 stdio JSON-RPC 驱动固定版本 `0.2.1-rc.2` 的无界面执行内核。独立 Node 子进程用于底层 ABI 兼容和任务隔离，不加载 Web 应用或监听 HTTP 端口。提示、执行事件和批准决定通过内部管道传递，密钥只通过经筛选的环境变量传入；临时配置不包含密钥，退出后删除。

`cupbox-engine.mjs` 是 Cupbox 自有适配插件：注册本机工具、对接批准、转发文本增量并提供只读历史查询。SDK 原生工具也必须经过 Cupbox 工具策略检查；写入和其他需要决定的操作经原生批准通道，不因旧会话曾用过高权限而自动放行。命令在沙箱模式下禁止，私有记忆、凭据和权限文件不能通过通用文件工具访问。

同一工作会话按 SDK 的 `session/resume` 恢复，工具结果按调用 ID 配对；后台子任务的文本不会混入主回复。SDK 子进程只存活于一次任务期间，任务完成后关闭，下一次从持久记录恢复。第三方匿名免费模型继续使用原有兼容执行器及其确认规则。

## 验证

- `node desktop/verify-harness-native.mjs`：本机模拟模型，验证真实读取、写入、原生工具、批准、续接及历史读取。
- `npx electron desktop/verify-harness-work.mjs`：实际 Cupbox 界面验证，涵盖目录选择、原生输入框和工具卡片、批准、恢复、停止，以及没有外部窗口或嵌入视图。
- 可将 `CUPBOX_HARNESS_IMPORT_FIXTURE` 指向上述内核测试生成的会话文件，额外验证旧记录导入；测试只使用 output 下的隔离资料。
- 单元测试：`test/harness-native.test.ts`、`test/harness-work-integration.test.ts`、`test/harness-host.test.ts`、`test/harness-sessions.test.ts`。
