# 多模型与项目工作流（1.0.2）

## 使用

1. 在 **设置 → 模型库与协作** 添加模型，填写独立名称、服务地址、模型 ID 和密钥，勾选实际支持的文本、视觉、绘图、语音、视频能力。
2. 展开对话输入框的 **调用能力与工作流**，勾选此次需要的能力，并为每项选择模型。单模型模式一次选择一项；多模型工作默认关闭。
3. 需要同时调用多个模型或自动拆分任务时，在设置开启 **多模型工作**。可选 1–3 个并发位置，并明确勾选参与项目制作的文本模型；未勾选时使用对话选择的文本模型。
4. 视觉分析先点击 **参考图片**，最多 4 张、每张 8 MB。图片在发送时上传到所选服务，文本历史会随当前请求发送。语音目前是文本转语音。
5. 子项目分栏显示真实排队、调用、完成或失败状态，可复制结果或仅重试失败子项目。图片、音频、视频保存到本机 `.cupbox/generations`；历史记录保留媒体地址及各子项目交付。

原有 **模型连接** 仍是默认文本连接；模型库密钥独立保存，公开给渲染进程的列表只包含“已配置密钥”状态。换服务地址或协议会清除旧密钥。模型库为本机 JSON 文件，沿用现有配置存储方式，不是系统凭据保险库。

## 工作流

| 工作流 | 行为 |
| --- | --- |
| 直接处理 | 调用此次勾选的能力，多模型开启时并行生成 |
| 规划 → 制作 → 整合 | 规划模型拆成 1–6 个独立子项目，逐一制作后统一整合 |
| 并行大项目 | 拆解独立子项目，在勾选的文本制作模型间轮流分配，按并发上限执行后整合 |
| 初稿 → 审阅 | 先生成初稿，再由所选审阅模型改进；可选择另一独立文本模型 |

规划、整合与审阅需要勾选文本能力。规划结果会校验任务数量和能力，不能调用未勾选的能力。规划遗漏的已选媒体能力仍会执行。每个阶段都有独立 API 调用，可能产生服务商费用。

并行子项目生成独立交付内容，不同时修改工作目录。**执行任务** 模式最后通过现有 Agent 和权限边界整合、按需执行本地工具；文件沙箱 / 本机运行及批准策略继续生效。应用不会把模型输出文字当成已落实到文件的证明。

## 接口适配

- 文本：OpenAI 兼容 `chat/completions` 或 Anthropic `messages`，支持原有工具循环。
- 视觉：上述两种协议的图片内容块。
- 绘图：`images/generations`，解析 `data[].b64_json`、`data[].url` 或硅基流动 `images[].url`；参数名称按服务类型适配。
- 语音：`audio/speech`，MP3 二进制结果，音色 ID 可编辑。
- 视频：目前适配硅基流动或同协议网关的 `video/submit` + `video/status`，每 5 秒查询一次、最多 15 分钟，完成后下载到本机。其他视频协议尚未适配。视频尺寸为 1280×720；图生视频可使用第一张参考图。

能力勾选是用户声明，不会自动改变服务商模型能力。服务商不兼容、欠费或参数不支持时，会显示真实失败状态；应用不伪造生成结果。

接口参考：[图片生成](https://api-docs.siliconflow.cn/docs/api/images-generations-post)、[语音生成](https://api-docs.siliconflow.cn/docs/api/audio-speech-post)、[视频提交](https://api-docs.siliconflow.cn/docs/api/video-submit-post)、[视频状态](https://api-docs.siliconflow.cn/docs/api/video-status-post)。

## 便捷操作与边界

- 顶栏 **−** 或 **Ctrl+M** 最小化当前窗口。
- **停止** 中断在途模型请求与后续调度，取消尚未批准的工具请求。已开始的本地操作会完成，服务端媒体任务可能继续运行并计费。
- 个别子项目失败不会抹掉其他已完成结果。工作流中止后的已完成子项目仍保留在对话中；规划阶段失败会恢复输入，方便重试。
- **导出** 保存 Markdown 对话和子项目内容，媒体引用为本机地址；移动到其他电脑时需另行携带媒体。
- 输入草稿保存在本机，下次启动恢复；发送成功或新建任务时清除。
- 测试采用本地 HTTP 模拟服务，覆盖真实 HTTP 请求、并发调度、媒体保存和 Electron IPC；未使用用户密钥验证付费服务。
