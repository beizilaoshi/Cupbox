# QQ 聚合点歌与概念版背景音乐（1.1.1）

聊天机器人 → 内容与日程 → 点歌：选择 Meting 免费聚合曲库，按 @ / 无需 @ 模式与自定义前缀搜索，选歌后获取可用音频，在本机转换为 QQ 语音。QQ 点歌不再依赖酷狗概念版登录。

## 设置 → 背景音乐：酷狗概念版登录

主窗口“设置 → 背景音乐 → 酷狗概念版 · 登录与在线曲库”提供五种登录方式。现有默认音乐登录凭证位置和加密方式保持兼容，QQ点歌页移除此登录卡片。

| 入口 | 使用方式 |
| --- | --- |
| 酷狗扫码 | 生成二维码，用酷狗概念版 App 扫码并确认 |
| 手机号 | 输入11位手机号，手动获取短信验证码，再输入4～8位验证码登录；同一手机号关联多个音乐账号时选择具体账号 |
| 账号密码 | 输入酷狗账号或绑定手机号及密码，可切换密码显示；成功、切换方式或退出时清空密码 |
| QQ | 生成独立的 QQ 音乐授权二维码，用QQ扫码，换取酷狗概念版登录 |
| 微信 | 生成独立的微信授权二维码，用微信扫码，完成开放平台音乐登录 |

三种扫码支持等待扫码、待确认、过期刷新和取消。切换方式会取消旧请求，迟到的授权不能覆盖新会话。短信只在用户点击时申请，没有自动重发；申请后60秒内不能重复获取，重开页面和软件也保留倒计时。发送结果不明时先检查手机，避免重复申请。密码、手机号和验证码不保存到登录档案，不进入聊天模型或日志。

页面右侧显示当前音乐身份，提供检查登录与退出。音乐账号与QQ机器人账号分别登录，不共用二维码。第三方授权或短信接口要求额外验证时，需按平台要求在手机完成，或改用其他登录方式；软件不会绕过验证。

登录后使用操作系统加密能力，将音乐账号 token、用户ID和稳定的本机请求标识保存在当前工作区的 `qq-bot/echo-music-session.json` 中，重开软件恢复。没有系统加密能力时拒绝保存，不写明文。每个机器人工作区独立保存音乐登录；状态接口只返回昵称、账号ID、登录方式、候选账号与扫码状态，不向界面、聊天模型或日志返回音乐 token、QQ OAuth cookie 或微信授权码。

背景音乐搜歌及取音频携带已保存的概念版凭证，沿用 user_verify → song_auth → song_url_auth 播放授权。搜歌后点击“加入本地歌单”，将可播放歌曲下载为本地歌单导入副本，再用现有背景音乐播放器播放。退出取消在途请求，不能改变歌曲权限。

机器人返回最多5首候选，再发送“点歌 1”至“点歌 5”（自定义前缀时沿用新前缀）。候选按账号、会话和请求用户隔离，5分钟过期。固定指令不调用聊天模型；自主聊天工具也发送歌曲音频附件，不能编造歌曲ID或直接传入任意音频地址。

QQ 点歌改为匿名 Meting 聚合：网易云、QQ音乐、酷狗、酷我并发搜索，展示来源与真实歌手；只按所选平台和ID取音频，不擅自替换其他翻唱或版本。平台没有免费播放地址、明确标记试听时提示换候选，不承诺全库免费完整。

无需额外部署服务。QQ聚合曲库仅提交搜索词和歌曲ID，不读取概念版登录。背景音乐概念版账号只用于本机搜歌和取得授权音频。匿名音频下载仅接受对应平台CDN域名，逐跳校验并固定公网IP。对本机代理198.18/15虚拟DNS，仅已知音乐域名可向固定HTTPS公共DNS回退；其他私网地址继续拒绝。

“仅本机常听歌曲”关闭在线搜索，已登记酷狗Hash以Meting公开音源解析。原有网易云/QQ数字ID登记保留但不参与此本机模式。语音转换仍限单曲10MB、10分钟，保留临时文件清理、取消与不重复发送。

QQ 官方机器人、微信、企业微信、飞书和钉钉暂不支持此 QQ 点歌语音入口，保存设置时会关闭 QQ 点歌开关。

## 实现来源

2026-10-26 按“获取音频文件，再转语音发送”实现完整本机转换链路。下载、解码、编码和发送各阶段记录脱敏进度；文件最多10MB、解码后最多10分钟，不静默截断。音频请求限定酷狗HTTPS域名，重定向逐跳验证并固定公共IP，拒绝HTML/播放列表/未知音频数据。FFmpeg以固定参数、单线程、隐藏窗口运行，仅接收临时本地文件；后台编码可取消，不阻塞界面。整体操作最多180秒，不能绕过账号或歌曲播放权限，失败不自动改发附件。

2026-10-26 群聊点歌支持独立触发模式：在点歌页选择“无需 @”或“必须 @”。默认无需 @、命令前缀为“点歌”；必须 @ 模式下搜索和编号选歌都需要实际 @ 机器人，引用回复不算 @。私聊不受群聊模式影响。自定义前缀可用“来首”“/music”等1～20字文字，按原文匹配（英文字母不区分大小写），搜索、选歌与帮助提示共用此前缀。设置示例实时预览，底部保存后生效；设置按账号工作区独立保存。

默认支持“点歌 晴天”“点歌晴天”“点歌：晴天”，候选后发“点歌 1”。仍遵守自动回复开关、会话白黑名单与睡眠策略，不抢答明确 @ 其他人的消息。搜索与选择按机器人、会话、用户隔离，五分钟过期；失效编号不会被当成歌名搜索。重复事件只处理一次，语音失败给出说明，送达状态未知不自动重发。点歌指令不调用聊天模型；模型点歌工具也遵守群聊 @ 模式。

- [EchoMusic](https://github.com/hoowhoami/EchoMusic) 的 [server 子模块](https://github.com/hoowhoami/EchoMusic/tree/main/server) 使用 [KuGouMusicApi](https://github.com/MakcRe/KuGouMusicApi)。本项目直接调用该 MIT 后端的搜索和歌曲地址模块，固定版本提交 `514f870db7e60ca37bc5535be5da36d32b571c6f`，没有复制 EchoMusic 的 GPL 桌面界面代码。
- 五种登录方式和字段依据原项目的 [user API](https://github.com/hoowhoami/EchoMusic/blob/main/src/renderer/api/user.ts) 与 [登录页](https://github.com/hoowhoami/EchoMusic/blob/main/src/renderer/views/Login.vue)；界面按 Cupbox 风格独立实现。
- NapCat 的音乐消息段依据[官方消息格式文档](https://napneko.github.io/develop/msg)。
- KuGouMusicApi 的 MIT 许可副本：`docs/licenses/KuGouMusicApi-MIT.txt`；运行依赖也保留原包许可证。

验收：本机使用真实 FFmpeg 解码 WAV 和 MP3，并在 Worker 中生成可解码的 QQ SILK；验证取消、清理、非法音频拒绝、@和前缀、凭据隔离及不重复发送。测试版 Electron 运行时也实际调用转换组件，未登录QQ或向真实会话发测试消息；QQ端接收和播放还需实际确认。


转换依赖固定为 ffmpeg-static 5.3.0（FFmpeg 6.1.1）和 silk-wasm 3.7.1。FFmpeg 作为独立进程运行，保留上游许可证与构建来源；许可副本位于 docs/licenses/ffmpeg-static-LICENSE.txt、ffmpeg-binary-LICENSE.txt、silk-wasm-MIT.txt，依赖包内也保留许可和 FFmpeg 构建说明。来源：[FFmpeg静态发行](https://github.com/eugeneware/ffmpeg-static)、[silk-wasm](https://github.com/idranme/silk-wasm)。


## 本轮参考与验证

参考 [Meting](https://github.com/metowolf/Meting)、[Listen 1](https://github.com/listen1/listen1_chrome_extension) 等。接入 MIT 的 @meting/core 1.6.2（许可 docs/licenses/Meting-MIT.txt），以独立可取消 Worker 调用四个平台的公开搜索和播放接口，不复制 Listen 1 界面。曲库宽度、免费播放权限和接口可用性不是一回事，不能保证所有平台、所有歌曲都能取得完整音频。

实测聚合候选、公开音频获取、下载、解码及SILK编码完整链路成功，样本音频约279秒；该样本是搜索返回的具体歌手版本，不能据此承诺其他版本可播。界面验证登录已移到背景音乐且QQ页无登录卡片；无真实QQ发消息。

在线搜索先对候选的原平台、原ID检查播放地址，跳过空地址和平台明确标记的试听版本；候选数量因此可能少于5首。选歌时重新取地址以应对权限或签名过期。没有公开音频时直接说明原因，不再给出统一的转换失败提示，不替换为其他歌手或录音。

点歌回复模式默认为“显示候选歌单”，收到结果后回复编号。“直接发送第一首”会在搜索前发送等待提示，将第一首可用结果转成语音发送，不展示歌单。等待提示默认为“我看看《{歌曲名}》在哪里呢，稍等一下～”，可在点歌页自定义，支持 {歌曲名} 占位符，留空恢复默认。两种模式均遵守群聊 @ 模式、前缀、允许范围和发送频率，不调用聊天模型。
