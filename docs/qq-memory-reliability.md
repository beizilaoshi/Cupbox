# QQ 本地记忆优化（2026-10-27）

本轮优先完成索引缓存、容量归档和召回反馈，同时补明确事实提取、按窗口压缩和排序修正。无需迁移已有聊天，第一次使用会自动建立派生索引。

- 每个账号的 `index.json` 保存检索条目与文件指纹。全局召回先在索引排序，再读取命中的来源文件；当前会话始终参与。指纹含修改时间、创建状态时间和大小，外部修改会使缓存失效。首次建索引需要读现有文件；以后仍检查文件元数据。
- 文件解析结果使用最多 128 项、32MB 的 LRU 缓存；对外返回副本，避免修改对象污染缓存。索引采用原子替换，连续检索期间最多约每秒持久化一次；漏存的派生索引会由原文件重新构建。持久化索引最多 32MB，超大账号的未缓存部分下次重建。
- 长期事实仍为每会话 1000 条、每用户 200 条。超额时只从相应容量范围选择未置顶项，优先保留过敏/禁忌，再按最近确认、召回频率保留。旧内容先写入账号下的 `archive/会话类型-号码/`，成功后才替换主文件。全部置顶时新内容归档，不挤掉置顶项。归档暂不自动参与召回。
- 每条事实附带的补充来源最多 30 项，序列化总大小不超过 4KB，原始主证据继续保留。面板“记忆管理 → 查看与整理”显示总体、单人最高容量与归档数；提示中可查看归档位置。
- `recall-usage.json` 单独保存稳定条目 ID、召回次数和最近召回时间。排名增加有上限的使用频率权重。召回测试不增加次数；统计损坏或写入失败不会阻断本轮召回，也不会覆盖损坏的统计文件。
- 明确第一人称的过敏、忌口、生日、居住地、职业、时区、家人宠物与约定可建立档案。“记住……”在开启自动保存记忆时，无需再开启自动整理。按句排除转述、假设和引号，不从 AI 答复推测事实，原有注入和敏感信息检查仍执行。
- 摘要只在活动窗口超过条数或 token 预算时更新，压缩后前移水位线。原始聊天仍按原有条数保存。BM25 先归一化、置顶改为倍率、未知日期按旧记录处理，旧版匹配不再重复计算衰减。
- 本机永久删除整个会话时，同时清理其归档、派生索引及召回统计；未增加 QQ 端删除权限。

## 验证

`test/qq-memory-reliability.test.ts` 覆盖 100 会话重启和暖缓存、外部编辑、删除、容量和全置顶、归档失败保护、证据字节上限、召回反馈、明确事实、窗口水位线和统计损坏。13 个相关测试文件共 139 项通过。

`desktop/verify-memory-reliability.mjs` 在隔离数据目录启动实际测试版，通过真实 IPC 验证容量和召回测试，并检查浅色/深色布局和渲染错误。一次本机运行：100 会话、200 条事实，已建索引后的重启召回读取 1 份聊天文件，约 14ms；暖缓存读取 0 份，约 10ms。耗时不是所有数据规模的保证，首次索引不计在这组数字中。

## 尚未更改的边界

主聊天 JSON 仍采用每会话原子整写，没有切换 SQLite、日志追加或批量合并主文件写入。没有加入本地向量模型、云端记忆服务、定期备份/完整迁移体系，以及通用的偏好改口历史状态。归档目前通过本机目录查看，未提供一键恢复界面。关闭自动记忆时，“记住……”也不会写入。
