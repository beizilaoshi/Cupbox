# 搜索与识别

当前行为：私聊直接发送图片或链接即可调用已开启能力；群聊仍要求同一条消息引用回复并@机器人。硅基视觉连接已用用户表情图实测成功，历史超时记录不能证明不支持图像。以下较早的修复记录保留作排查历史，以末尾私聊入口修复记录为准。

## QQ 图片下载修复（2026-10-26）

修复当前 NapCat 图片 CDN `multimedia.nt.qq.com.cn` 在系统代理 Fake-IP DNS 下被误判为非公网的问题。仅为该精确主机启用已有的公共 DNS 校验：仍拒绝私网、环回、链路本地和伪造域名，连接固定到校验后的公网地址，重定向逐跳重新检查。图片失败日志补充所选模型、错误代码和脱敏原因。

实测此前失败的 QQ 原图已返回 HTTP 200（236177 字节 JPEG），相关 73 项回归通过。当前普通图片识别连接“硅基”另有连接超时问题；用户选择保留该连接自行检查，未更换模型、未修改任何账号设置。修复已同步现用可视化目录，完整退出并重开后生效。引用＋实际@的触发限制保持不变。

QQ机器人 → 聊天设置 → 搜索与识别。网页搜索、网页获取、图片识别及短视频解析在私聊中直接发送即可使用；群聊必须在**同一条消息**中同时包含真实引用回复段和指向当前机器人的 @ 段，引用消息中的文字“@”不算。群聊单独发图、发链接、只引用、只@、主动插话均没有这些能力。原有会话范围、自动回复开关和睡眠模式仍生效。合并消息不会把不同消息里的引用和@拼成授权。

## 能力

- 网页搜索：启用原有搜索开关后，通过公开搜索返回标题、摘要、链接；回复应引用来源。网页获取另有开关和128KB大小限制，压缩解码后也检查限制。
- 图片识别：选择实际支持图片输入的视觉模型。读取本条及同会话内被引用消息中的图片，必要时通过QQ的 `get_image` 取得图片地址。拒绝跨群引用图片、内网地址和非位图，最多5张，每张5MB，总计8MB，下载与识别合计时限105秒。
- 短视频解析：默认关闭，尝试抖音/快手/哔哩哔哩/小红书公开页面与平台短链；取得页面标题、简介、作者和原链接。分享卡片只提取URL，不运行网页脚本或验证代码。
- 视频画面：独立开关，需同时启用图片识别并配置视觉模型。公开完整MP4最多10MB，使用本机FFmpeg对前180秒抽样生成拼图；短片会补齐末帧。没有公开视频文件时可只分析封面。音轨转写由独立开关控制，不把标题、封面或抽样当作完整视频。

内容按不可信外部资料注入模型，按已取得的证据自然回应。未获取资料、登录验证、权限不足、过大、解码或视觉接口失败均保留明确原因，不假称看过视频。解析不使用私人Cookie或额外解析服务，不绕过平台验证。

下载重定向只在原平台域名中进行，音视频只允许原平台CDN；DNS固定公网地址，拒绝私网。系统代理产生198.18/198.19虚拟IP时，已知平台可向固定HTTPS公共DNS查询真实公网地址，仍验证并固定地址。媒体临时文件处理后清理。不向QQ发送原视频、不执行真实群管理操作。

## 验证范围

自动化覆盖引用/@组合、合并消息权限、跨群引用、图片补全、平台域名、跳转限制、gzip解码上限、仅标题/封面/抽帧证据区分、取消、MP4真实抽帧和临时文件清理，并通过本机模拟模型接口检验工具与图片传递。

本机实网测试：公开网页搜索与B站示例的标题/作者/封面可获取；示例完整视频超10MB时按限制拒绝。抖音示例返回验证页面，明确报告未解析成功。现有视觉连接“朋友”对红色圆形测试图识别成功；“硅基”连接25秒测试超时，未修改用户模型配置。接口状态和平台页面可能变化，不能将某个公开示例成功当作全平台可用保证。

页面数据格式参考：[yt-dlp 抖音提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/tiktok.py)、[小红书提取器](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/xiaohongshu.py)。未引入yt-dlp程序或Cookie处理。

## 抖音解析修复

参考 [media-parser 的公开作品接口与分享页文档](https://github.com/ucmao/media-parser/blob/main/docs/parsers/douyin.md) 和 [AstrBot 分享解析器](https://github.com/xuanxuan123xuan/astrbot_plugin_share_forward/blob/master/parsers/douyin.py)，新增匿名公开作品信息通道，获取不到时回退移动分享页。必须在返回列表中精确匹配请求的 `aweme_id`，接口仅返回推荐视频时拒绝用其他作品替代。优先选择较小的原平台码率版本，降低10MB限制下下载失败的概率。不计算签名、不使用Cookie、不运行验证脚本。

QQ引用自动附带其他人的@时，只要同条消息确有引用和对机器人的@，仍满足条件。合格请求直接处理，不等待消息合并；向模型明确区分“已满足触发条件”“解析开关关闭”“平台读取失败”，避免反复要求引用和@。

实测在本机会话记录中找到的原始抖音短链已成功核对到目标作品，获取真实标题和作者，下载约23.6秒的视频并抽帧。短片按实际时长均匀取样，最长取前180秒；音轨转写见下文。

## B站画面与音轨修复（2026-10-26）

后续排查补充：普通图片原选择的“硅基”视觉请求实测30秒超时，同一张图在“朋友”连接识别成功；已备份并调整当前账号的图片模型，聊天模型保持不变。QQ协议字符串格式（CQ）在接收边界转换为消息段，数组中的普通文本不解析成权限标记；引用消息也兼容此格式。私聊允许读取协议确认来自当前用户的旧消息，无需依赖重启后已经丢失的临时收件箱；其他用户和其他群的引用仍拒绝。日志分别记录引用取得、触发权限、画面/音轨结果和具体失败原因。

实际Electron桌面链路进一步复现：图片下载97毫秒，视觉请求39,104毫秒，原来的30秒总时限会在模型返回前取消。合计时限调整为60秒后，协议字符串引用图片经完整接收、识别、生成及本地发送拦截成功，最终回复正确包含人物描述和封面文字。诊断新增下载开始/结束、视觉开始/结束及耗时；不将模型慢响应误报为图片缺失。594项自动化测试通过，测试过程不向真实QQ发消息。

媒体下载补充标准浏览器 User-Agent，修复B站CDN返回403。完整MP4只下载一次，临时目录中分别生成六帧拼图和最多180秒的16kHz单声道PCM WAV；画面分析与语音转写并行，任一失败保留另一路证据及具体原因。视频可单独选择视觉和音频模型，转写无需开启普通聊天语音识别。新账号两个开关仍默认关闭，原有引用＋@限制继续生效。语音接口使用标准 [audio/transcriptions](https://docs.siliconflow.cn/docs/api/audio-transcriptions-post)。

实测用户截图中的 BV1peJf6XE3Z：下载1,397,423字节MP4，获得六帧拼图与约72.2秒音轨；现有“朋友”连接识别画面成功，SenseVoiceSmall实际转写成功，包含账号交接、智能工作台、代码生成画面、配音及每日发布安排。当前账号已单独配置视频模型并开启画面和音轨，修改前备份设置及模型库。测试不发送真实QQ消息。587项回归及隔离Electron页面验证通过。

## 私聊实际入口修复与硅基验证
