# 办公文档工具（1.1.0）

目前共 **23 项**。本地工具的“办公”分类可按 **Word / PPT / Excel / PDF / 格式交换** 筛选；AI、QQ 主人工作模式及工作流共享同一套执行和权限边界。

入口：**设置 → 任务与工具 → 办公与开发**。顶部示例按钮会填入可修改的示例，点击并不会执行。主对话切换 Agent 工作模式后也可直接描述需求，例如“读取项目里的报价.xlsx，整理成 Word 报告和 6 页 PPT，先给我预览”。

外部工具箱：**本地工具 → 办公**，提供23张独立工具卡。Word 正文可直接输入，多级标题用 `#` / `##` / `###`，项目符号用 `-`；PPT 每页以独立一行 `---` 分隔，首行是页标题；Excel 可直接粘贴 Tab 分列的表格，首行作表头；单元格修改使用每行 `A1=新内容`。这里无需 JSON 或模型配置，可按五个分组筛选。选择“填写示例”只填表，点击“预览文件”后才准备预览，再由“执行这次预览”提交。表单修改会使旧预览失效。

工作流：**对话框 → 调用能力与工作流 → 办公工作流**，提供 Word 报告、PPT 汇报、Excel 整理、办公交付套件四个草稿模板。点击切换为执行任务并选择文本能力，填入场景及验收要求；请修改占位路径后手动发送。有现有草稿时不会覆盖，也不会自动开启多模型。单模型可直接执行；启用多模型后可选规划、并行或审阅。办公场景的工具及读回要求同时传递给协调模型和执行子项目。

另新增 **模板批量填充、表格清洗与统计、PDF 整理、格式交换与归档**，共八个办公工作流模板。

## 增强的16项能力

| `word_template` | 填充正文、表格及页眉页脚里的 `{{变量名}}`；所有指定变量必须命中 |

| `ppt_reorder` | 调整真实放映顺序，需列出全部页面且不重复，不删除页面 |
| `excel_analyze` | 本地计算数值列合计、均值、极值、空值、重复行和按表头分组汇总 |
| `excel_transform` | 按表头筛选、排序和去重，输出新数据表 |
| `excel_format` | 颜色、加粗、对齐、边框、数字格式、列宽和冻结首行 |
| `excel_merge` | 合并多个文件里表头完全一致的指定数据区域 |
| `office_import_csv` | UTF-8 CSV/TSV 转 XLSX；默认保留文字，显式开启后才转换安全数字 |

| `pdf_create` | 中文 A4 文字报告、自动换行分页和页码；使用本机 Windows 黑体 |
| `pdf_merge` | 按顺序合并最多10份 PDF，总计不超过500页 |
| `pdf_extract` | 抽取或重排最多200页，保留源文件 |
| `pdf_stamp` | 添加可见文字水印；不会删除下层内容，不能用于安全脱敏 |

外部表单中，替换使用“旧文字 → 新文字”；模板变量用“变量名=值”；批量套印以 Tab 分列，首列标题必须是 `path`，后续列为变量名。PDF 抽页支持 `1,3-5,2` 这样的范围。其他参数可在设置的办公与开发工具中调整，或直接交给 AI 调用。

Excel 清洗、合并与统计只使用指定区域，不猜测表头对应。清洗和合并输出普通数据表，原格式不复制；遇到公式或复杂单元格时会要求明确处理，不拿缓存当本次计算结果。统计会单列公式数量，只有真实数值参与计算。每次增强区域操作最多20000格，合并输出最多10000行；普通分页读取仍为1000格。CSV 导出会处理以 `= + - @` 开头的文字，防止打开时被当成公式。

PDF 操作不运行脚本、外链或自动动作，含脚本/自动动作/附件或加密的文件会拒绝处理。生成 PDF 仅做文字排版，不提供 Word/PPT 原视觉排版的保真转换；扫描件不做假识别。PDF 重写会使原数字签名失效，部分书签、表单或其他高级结构不保留，请优先另存。

QQ：在 **工作模式** 下开启“允许主人申请本地文件操作”，配置主人 QQ 并在主窗口选择工作目录。只有主人可申请，每项办公工具仍需本机批准。文档正文可能发往所选模型并出现在 QQ 回复里；不会自动把原文件发给群友。

## 预览和权限

写操作第一次默认只预览，提供内容摘要、路径和确认令牌。实际提交必须使用相同参数，并增加 `dryRun:false`、`confirmToken`。预览不是交付完成；需提交成功并再读取确认。主对话沿用当前批准方式；QQ 始终逐项本机批准。

默认不覆盖目标文件。确需覆盖时加 `overwrite:true`。原文件在预览后变化会报冲突；修改 Excel 时源文件变化也要求重新预览。成功提交返回操作 ID，可通过 `fs_rollback` 预览并恢复。文件工具开关、预设插件开关、沙箱路径、保护目录和子项目写入边界同样生效。

## 范围与限制

- 支持 `.docx` / `.pptx` / `.xlsx`。旧版 `.doc` / `.ppt` / `.xls`、密码加密文件、宏和嵌入程序不支持。
- 阅读提取文字与结构，不会自动对文档图片、图表或扫描页进行视觉识别。
- Word/PPT 创建生成新文稿，不是保留既有复杂排版的原位编辑器。Excel 更新可能丢失不受库支持的复杂图表、透视表或其他高级对象，优先另存并核对。
- 公式需显式传 `{formula:"SUM(B2:B3)",result:30}`；普通以 `=` 开头的字符串仍是文字。只支持本工作表引用和一组常用函数，拒绝外部引用与网络函数。程序不会计算公式；已有结果可能过期，由 Excel 打开后重新计算。
- 输入文件最多 16MB，ZIP 条目数量及展开体积受限。每次 Excel 读取最多1000格、30000字符；Word/PPT 返回结果可分页，避免整份文件消耗上下文。

## 复用与许可

文档生成基于 [docx](https://github.com/dolanmiu/docx)，演示生成基于 [PptxGenJS](https://github.com/gitbrent/PptxGenJS)，表格读写基于 [ExcelJS](https://github.com/exceljs/exceljs)，XML 解析基于 [fast-xml-parser](https://github.com/NaturalIntelligence/fast-xml-parser)，均保留依赖包许可。生产依赖递归打包，不依赖开发机全局工具。

现有文档修改使用 [xmldom](https://github.com/xmldom/xmldom) 与 JSZip；PDF 页处理使用 [pdf-lib](https://pdf-lib.js.org/)，文字层读取使用 [PDF.js](https://github.com/mozilla/pdf.js)。这些库不会替代应用自身的文件权限、大小限制、输入检查和预览提交机制。

依赖固定版本；对 PptxGenJS 的 image-size 及 ExcelJS 的 uuid 使用修补版本覆盖，相关真实生成与读取回归通过。仓库已有的其他依赖审计项不属于本次办公能力修改范围。
