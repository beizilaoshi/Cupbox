# 多平台连接与运行（1.1.1）

入口仍在主窗口的 QQ 机器人工作台，进入后选择 **连接与运行**。本轮重排为顶部平台选择、左侧账号工作区、右侧“连接配置 / 运行状态 / 更多设置”。页面和设置字段沿用原有保存流程，不复制出第二套配置。

平台选择是草稿，底部“保存所有设置”后生效。密钥在配置卡片中单独点击“加密保存凭证”；保存凭证不会启动连接或开启自动回复。切换编辑账号不会停止其他实例。关闭工作台或退出应用会停止全部连接。

## 接入方式

| 平台 | 配置方式 | 本轮能力 |
| --- | --- | --- |
| QQ / NapCat | 原有个人 QQ 扫码 | 保留原有 QQ 能力 |
| QQ 官方机器人 | AppID、AppSecret | 保留上一轮官方文字与图片适配 |
| 微信 | 个人微信扫码，腾讯 iLink 通道 | 接收与回复单聊文字；保存登录凭证与同步游标 |
| 企业微信 | API 模式智能机器人 BotID、Secret | 长连接接收单聊与群聊文字、平台已转写的语音文字；使用原回调帧回复 |
| 飞书 | 企业自建应用 AppID、AppSecret | 长连接接收单聊和群内 @ 的文字；回复原消息 |
| 钉钉 | 企业内部机器人 ClientID、ClientSecret，Stream 模式 | Stream 接收单聊、群内 @ 的文字；使用原事件的临时会话地址回复 |

四个新增平台先提供**文字收发**，沿用模型、人设、记忆、关系成长、固定睡眠回复和已启用的文字能力。尚未适配的图片、音频素材、QQ 空间、戳戳、点赞、点歌、传话、主动推送、本地文件工具、多段发送等会在这些平台停用。企业微信的语音转成文字由平台完成，不请求 Cupbox ASR。

## 个人微信扫码

1. 新建或选择一个独立账号工作区，点击“微信”，保存设置。
2. 点击“连接微信”；首次使用生成二维码，用个人微信扫码并在手机确认。
3. 如微信要求输入手机显示的验证数字，在本机配置卡片里提交。数字只用于当前登录，不保存进设置、记忆或日志。
4. 登录成功后等待消息同步通道在线，再配置模型和自动回复。
5. 下次可用加密保存的凭证恢复连接；失效时点击“扫码 / 重新绑定”。扫码五分钟超时后停止，不无限刷新二维码。

此方式连接的是腾讯提供的微信 ClawBot / iLink 会话，不接管微信客户端，也不读取个人微信的全部好友、群和历史聊天。是否能够绑定和使用取决于微信当前开放范围。此版本只处理服务端投递的单聊文字，不支持微信群。

## 企业微信

在企业微信创建 **API 模式智能机器人**，选择长连接，获取 BotID 和 Secret。这里不是“只有一个发送 Webhook 地址”的群机器人。保存密钥、保存平台选择后连接，等待认证成功。参考[企业微信官方 SDK](https://github.com/WecomTeam/aibot-node-sdk)。

## 飞书

在[飞书开发者后台](https://open.feishu.cn/app)创建企业自建应用，启用机器人。开通所需收发消息权限，订阅 `im.message.receive_v1`，使用长连接事件订阅并发布版本，检查应用可用范围。填写 AppID、AppSecret 后保存连接。适配器先获取自身机器人标识，再判断真实 @，不会把 @ 其他机器人当成 @ 自己。

参考[飞书长连接文档](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)和[飞书官方 Node SDK](https://github.com/larksuite/node-sdk)。

## 钉钉

在[钉钉开发者后台](https://open-dev.dingtalk.com/)创建企业内部应用，添加机器人能力，选择 Stream 模式并发布。填写 ClientID（AppKey）、ClientSecret（AppSecret），检查应用和机器人可用范围。接收 Stream 回调后先确认事件接收，再异步处理模型回复，避免等待模型期间平台重投。

仅向本轮事件提供的官方临时 `sessionWebhook` 回复，不使用用户在聊天中提供的网址，不在回复地址过期后主动补发。消息提交只根据平台实际确认信息记录，不保证用户已经阅读。协议参考[钉钉官方 Stream SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-nodejs)。

## 数据与连接限制

- 每个账号工作区配置独立，最多保存 8 套，最多同时运行 4 个实例，可混用平台。
- 企业平台密钥、微信 token 和游标使用系统加密存储，保存在当前账号目录 `qq-bot/channels/<平台>.json`。不会出现在普通设置、状态 IPC、模型提示或诊断里。加密不可用时拒绝保存。
- 微信与企业平台原生用户、群标识映射为稳定的 15 位本机标识。回复名单和用户档案使用配置卡片里显示的**本机标识**，不是个人 QQ 号。
- 记忆按账号工作区、平台、机器人/应用 ID 和会话分开，位于 QQ 记忆根目录 `channels/<平台>/<应用指纹>`，不会与原有 QQ 记忆混用。
- 回复路由绑定原事件的账号、会话、发言人和消息编号。只接受已收到事件的有效回复上下文；本机上限四分钟，平台实际窗口以接口为准。
- 发送结果未知不自动重试；长连接与消息拉取可进行有界退避重连。停止会取消轮询、重连和待处理回复；已提交的平台消息无法撤回。
- 更新了刷新导航规则：仅允许工作台自身可信文件重载，其他页面导航仍阻止。切换账号现在会实际重载界面，清除旧账号草稿状态。

## 验证范围

`test/qq-channels.test.ts` 覆盖平台限制、加密凭证隔离、长整数消息ID、重复投递、回复路由、企业微信回调、飞书自身@判断与快速事件确认、钉钉网关和回调地址限制、微信扫码确认/游标/上下文、验证数字、登录失效及现有聊天引擎的四平台记忆隔离。

`desktop/verify-qq-channels.mjs` 在独立测试目录检查实际打包目录的 SDK 加载、系统加密保存、页面分区、平台选择持久化、账号真实重载和 960×680 布局。使用虚构凭证，不连接真实平台或发送真实聊天消息；真实账号连通性需要用户按各平台要求配置后验证。

## 来源与许可

微信 HTTP 字段依据[腾讯微信通道源码](https://github.com/Tencent/openclaw-weixin)，本适配器独立实现，不依赖 OpenClaw。钉钉 Stream 帧格式依据官方 SDK，并在本地实现以控制错误脱敏及连接生命周期。两者的 MIT 许可副本位于 `docs/licenses/`。企业微信与飞书使用各自官方 SDK，运行依赖保留原包许可。
