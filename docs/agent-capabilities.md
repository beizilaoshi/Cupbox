# Agent 文件交付与记忆

桌面版使用「工作模式」才会调用工具；问答模式只做文字分析。模型收到的能力说明取自本次最终工具清单，包含预设、工具开关、运行环境、模型通道与子任务范围过滤的结果。

未选择工作文件夹时，工作模式使用应用数据目录下的 `sandbox` 作为默认文件交付目录。通常位于系统文档目录的 `Cupbox/sandbox`；自定义数据位置时以界面「权限与运行环境」显示的目录为准。可以点击「打开默认目录」查看结果。需要编辑已有项目时，先选择该项目文件夹；已有会话保留自己的工作目录，切换项目后请新建会话。

文件读取与写入使用现有 `fs_read` / `fs_write` 等工作区工具。文件不能越出工作区，也不能通过符号链接或 junction 绕过范围。写入先返回预览和令牌，再使用相同参数提交；文件变化会使预览失效。批准方式沿用用户设置，敏感路径和应用授权存储继续受保护。

命令使用现有 `run` 工具。本机模式下，白名单来自用户通过「开发与授权」批准的项目策略；模型传入 `allowPrefixes` 不会授予权限。命令每次仍需人工批准。文件沙箱模式不提供命令、终端、Git 或包脚本执行能力。本机命令的工作目录并不是操作系统沙箱，批准前应核对完整命令。

`memory_manage` 与 `memory_recall` 都返回常驻画像和协作约定，分别标注 `memory/user.md`、`memory/memory.md` 来源。事实数量为 0 时，画像仍会显示并计入 `runtimeEntries`。画像通过 `memory_profile` 编辑，不重复复制成事实。

项目记忆工具统一查询旧的 `memory/facts.jsonl` 和 `scoped-state.json`，每条事实标明存储来源。默认只查询当前项目事实，`scope:global` 查询全局事实；其他项目的事实不会返回。遗忘只按当前范围中的精确 ID 删除，不会清空画像或其他项目。两种事实存储均保留原位置，无需迁移已有数据。

MCP 的禁用清单同时作用于嵌套 `ai_agent`，防止通过 Agent 重新调用已禁用的工具。本次新增的默认工作区接入属于桌面版，CLI/MCP 的独立文件工具接口没有扩展。
