# 回复、评价与场景工作流

## 回复阅读与复制

回复现在通过 Marked 解析 Markdown，再用 DOMPurify 清理后显示。支持标题、强调、列表、引用、表格、行内代码和代码块。原有 Markdown 原文继续保存在会话中，便于导出和复制。

- **复制内容**：复制适合直接粘贴阅读的正文，保留代码内容。
- **复制 Markdown**：复制模型原文。
- **复制代码**：只复制对应代码块。
- 回复不执行 HTML 脚本或事件，不自动加载 Markdown 中的远程图片；HTTPS 链接经应用外链入口打开。生成接口的媒体继续由原有媒体组件展示。
- 工具轨迹默认折叠，文件工具使用中文名称；子项目也支持相同的 Markdown 排版。

## 评价如何影响上下文

| 操作 | 后续行为 |
| --- | --- |
| 有帮助 | 最近三条好评答复作为有长度上限的优先参考；不会自动变成长期事实 |
| 不准确 | 从之后发送的历史中排除这条助手答复，清除可能包含它的旧摘要，撤销由这条回复的“记住”操作保存的事实 |
| 再次点击评价 | 撤销该评价，之后重新按普通历史处理 |
| 记住… | 打开可编辑内容，只有点击“保存到记忆”后，才写入现有长期事实存储供相关任务召回 |
| 已记住 | 可修改或移除对应的长期记忆 |

历史记录仍保留原文和评价，方便复查。用户问题不会因为助手答复被差评而删除。评价只控制对应答复及其明确保存的记忆，不推断其他独立记忆是否正确。已发送的请求不会被事后评价追溯修改；当前任务运行时暂不接受评价变更。新建会话不会自动带入其他会话的普通好评历史；明确保存的长期记忆则可跨会话召回。

## 场景与流程

输入框展开“调用能力与工作流”后可选择自动识别、通用、开发与修复、调研与分析、写作与文案、数据与表格、多媒体创作，并填写自己的验收标准。

- **智能选择流程**：简单任务直接处理，较复杂开发任务使用项目流程，其他复杂任务采用顺序流程。
- **依赖调度**：规划输出任务 ID 与 `dependsOn`。应用校验依赖是否合法、是否循环，再按就绪状态启动。下游会得到上游文字、媒体和交付目录。失败任务的下游会标记为阻塞，不假装完成。
- **质量检查**：快速交付省略检查；“交付后检查”增加一次模型审阅；“检查并修正一次”最多修正一次并复检。审阅结果明确标注为模型判断，不能替代真正运行测试的工具证据。
- **执行模式**：子项目可使用文件工具实际制作成果，每个子项目只写自己的 `.cupbox-deliveries/<运行 ID>/<子项目>` 目录，避免并行覆盖。协调模型可读取这些成果，按权限策略整合到工作目录。
- **问答模式**：输出分析或交付内容，不调用本地文件工具。调研场景没有内置互联网搜索工具，不会虚构已联网查询；应提供资料，或使用可用工具取得来源。

多模型工作仍默认关闭。规划、制作、审阅、修正均可能产生额外服务商调用费用，实际模型能力取决于所配置服务。

## 官方文件工具复用

桌面端直接调用官方 `@modelcontextprotocol/server-filesystem` 的 stdio 服务，通过已有 MCP SDK 通信。没有重新实现文件编辑算法。

提供 10 项能力：读取文本、读取多个文件、写入文件、精确编辑、创建目录、列出目录、查看目录大小、目录树、查找文件、文件信息。可在“工具管理”中关闭扩展文件工具。

服务仅允许访问选定工作目录。沙箱模式还在 Node 权限受限进程中运行，禁止子进程和网络，文件写入限制在沙箱。智能批准对读取自动放行，对修改请求批准；请求批准与完全控制沿用原有策略。停止请求会关闭该轮文件服务；已开始的文件变更不承诺回滚。没有工作目录时不提供这些文件能力，原有其他工具仍可用。

便携包携带 Node 24+ 的 Electron 运行时及完整生产依赖，无需临时从网络安装 MCP 服务。

## 开源来源与验证

- [Marked](https://github.com/markedjs/marked)：Markdown 解析，使用兼容项目运行环境的 15.x。
- [DOMPurify](https://github.com/cure53/DOMPurify)：渲染前清理。
- [官方 MCP Filesystem](https://github.com/modelcontextprotocol/servers/tree/main/src/filesystem)：文件操作与目录限制。
- 调研了 [LangGraph 的工作流模式](https://github.com/langchain-ai/langgraphjs)；此项目沿用自己的模型接入和会话层实现依赖调度，没有引入整套 LangGraph 框架。

库版本锁定在 `package-lock.json`。第三方许可原文保留在包及 `desktop/ui/vendor/` 中。接口联调使用本地模拟模型服务；文件读写、进程权限与批准、评价持久化、后续请求过滤均通过真实 Electron IPC 验证，没有使用用户真实模型密钥。
