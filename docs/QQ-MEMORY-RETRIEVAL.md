# 本地中文混合记忆检索

参考 [Mem0 的过滤、混合检索和评分解释](https://github.com/mem0ai/mem0/blob/main/docs/core-concepts/memory-operations/search.mdx)，在 Cupbox 原有本地文件记忆、来源隔离、去重和衰减机制上重新实现检索层。没有安装或接入 Mem0 服务，没有上传本机记忆，没有增加 embedding / rerank API 请求。不是完整向量语义搜索。

## 修复的问题

- 原先中文单字交集易误召回，换成饮料/兴趣等问法也可能漏掉原话。现在使用 Intl 中文分词、二元词项、BM25评分和有限的主题词扩展。
- 原先共享近期聊天和笔记在前，偏好在后，整体截断可能让偏好完全消失。现在统一排序、去重、按完整条目装入预算，默认3000总预算下召回部分约570 token，并留余量给主流程。
- 原先关闭模型记忆工具后，已保存事实不参与召回。现在读已有事实只需要自动记忆开启；模型写入工具仍保持原有权限和开关。
- 原先最近100个源可能没有当前会话。现在始终先纳入当前会话，再选择最多99个最近允许共享的源。
- “你记得我喜欢什么吗”等个人档案问题按当前协议 QQ 匹配，不将其他人的偏好当成本人；一般主题查询仍允许在已授权的共享范围内返回其他人的带来源记忆。
- 对明确的、相同对象的喜欢/不喜欢表述，发现同一用户较新相反原话时降低旧说法排序，并给模型时间提示。不会删除历史，不能处理所有自然语言矛盾。

## 使用

QQ机器人 → 记忆管理 → 查看与整理 → 中文混合检索与召回测试。

默认中文混合检索，可切回旧版字词匹配。先选择已有的账号与会话；群聊测试填写当前发言人的 QQ，私聊自动使用会话 QQ。输入普通问题，查看扫描数量、候选、命中、注入条数、token预算，以及每条来源、发言人和排名原因。使用已保存规则，不调用模型、不发 QQ 消息、不写入记忆。运行日志只记召回数量，不记正文。

文件结构、现有资料和共享范围不变，无需迁移。仍遵守原来每会话最近200条对话、每人最多50条聊天笔记、每会话500条笔记和长期事实容量；超出这些保存上限且没有摘要/事实留下的内容，检索无法恢复。长期事实仍由原有工具或本机编辑流程写入；本次不自动推断新事实。

验证：`test/qq-memory-retrieval.test.ts` 和原有记忆、共享、上下文、陪伴测试；`desktop/verify-qq-memory-retrieval.mjs` 在隔离 Electron 中验证实际 IPC、召回解释、模式保存和窄屏布局。
