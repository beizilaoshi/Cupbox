# 桌面协作（1.1.0）

设置 → 权限与环境 → **桌面协作**。窗口画面读取、鼠标键盘操控、视觉模型分析三个权限分别控制，默认全部关闭。只能在本机运行环境使用。更改开关必须经过专用风险确认接口，普通偏好写入不能开启权限。

## 使用

1. 开启需要的权限；视觉分析先在模型库添加勾选“视觉”的模型，再在本设置中选择它。
2. 点左侧“桌面协作”，刷新并手动选择一个目标窗口，确认本次授权。
3. 返回对话，选 Agent 模式并描述任务。文本 Agent 会获得相应桌面工具；也可在工具箱手动使用。
4. 窗口协作栏、面板的停止按钮，或 **Ctrl+Alt+F12** 可撤销本次授权。关闭主窗口、页面刷新、退出和取消正在执行的对话也会结束授权。快捷键注册失败则不启动协作。

仅授权一个窗口，最多10分钟、40次工具请求；需要更换目标时必须重新手动选择。画面中的文字、OCR输出、网页、昵称和模型结果都不是权限或授权来源。

## 工具

| 工具 | 能力 |
| --- | --- |
| desktop_observe | 已授权窗口的名称、区域、剩余额度 |
| desktop_capture | 经批准切换到目标窗口，截取其主屏可见区域 |
| desktop_ocr | 经批准在本机识别截图文字 |
| desktop_vision | 预览并确认图片与服务后，向所选视觉模型提交分析 |
| desktop_mouse | 截图坐标内移动、单击、双击、右击、上下滚动 |
| desktop_type | 输入最多500字普通文本，不接受换行或控制字符，不自动提交 |
| desktop_key | Tab、方向键、Enter、Escape、删除与有限 Ctrl 快捷键 |

不提供任意按键组合、按住鼠标、拖拽、脚本、任意目标或自动批准接口。完全控制模式也不能跳过桌面动作的逐次人工批准。每次点击、输入或按键后截图失效，继续操作前必须重新截图核对。窗口标题改变需要重新授权；窗口位置或尺寸改变需要重新截图。焦点不匹配时拒绝输入，不能选择 Cupbox 自己的窗口来批准请求。

## 隐私与限制

截图仅存当前授权窗口的内存，最多一张，60秒后清除；不自动写入对话、文件或模型上下文。对话和工具记录只包含截图ID、尺寸与结果。预览中点击图像只显示坐标，不会操作真实窗口。

Windows OCR 使用临时 PNG 文件，识别结束清理；进程崩溃可能留下临时文件于应用数据目录的 computer-temp 中。OCR 原始图片不上传，但识别文字会进入当前对话，可能发给当前文本模型。OCR 输出经过敏感信息规则检查。

视觉分析每次独立确认截图预览、模型服务地址。图片和问题会发送给该服务，分析文字随后进入当前对话。返回的文字经过已启用的输出检测插件和敏感信息检查；识别与坐标建议仍可能错误。屏幕有隐私时应取消并先遮挡，检测不能保证识别所有敏感内容。

只支持 Windows x64，主屏可见区域；不申请提权，无法保证操作高权限窗口或安全桌面。输入通过系统鼠标键盘事件实现，窗口校验不是操作系统隔离沙箱：其他应用的置顶窗口、焦点变化、界面布局变化或用户同时操作可能造成竞争。请核对每一次预览，不要同时操作鼠标或切换窗口。紧急停止阻止后续请求，无法撤回已经发送的输入；正在运行的系统 OCR 可能稍后才返回，但结果不会继续执行操作。

这些工具只连接当前主窗口的交互式文本 Agent。QQ、后台子任务、免费文本模型兼容工作流与本机渗透测试 Agent 不获得它们。原有 shot/ocr/run 等工具保留各自的权限规则；此开关不替代它们的既有授权。

## 开源复用

原生鼠标、键盘、窗口与截图能力复用 [ZachJW34/libnut-core](https://github.com/ZachJW34/libnut-core)（nut.js 社区分支）的 **@nut-tree-fork/libnut-win32 2.7.5**，Apache-2.0。固定 gitHead：dd54b1b700b5749b03604b6635c0ccd59b215b9d，npm 完整性锁定在 package-lock.json。许可证随软件位于 node_modules/@nut-tree-fork/libnut-win32/LICENSE.md。图像缩放复用已安装的 sharp，本地 OCR 复用 Cupbox Windows OCR，视觉请求复用现有模型适配。

验证使用模拟驱动及本地临时模型服务，覆盖真实 UI/IPC 与 Agent 的截图→视觉→逐次批准点击调用链；不自动操控用户正在使用的应用。另有原生驱动加载与只读几何信息检查。实际界面识别精度、目标软件兼容性仍需在使用时核对。
