# 戳一戳回复修复

版本保持 1.1.1，源文件和测试运行目录均已更新。后台模块在 Cupbox 主进程中加载，需要从托盘退出软件后重开；只关闭窗口或重启 QQ 协议端不足以重新加载这些模块。

修复内容：

- 统一标准 `notice.notify.poke` 与直接 `notice_type=poke` 通知，私聊按 NapCat 的 `sender_id` 识别真实发起人，旧事件缺少该字段时使用 `user_id`。机器人自身发起、目标不是机器人、目标缺失、无效账号与群号不进入回复流程。
- 内部 Symbol 标记戳戳动作，普通 QQ 文本无法伪造这个触发。群聊戳戳不再依赖 @ 或关键词规则，预设和 AI 共用一致的会话权限判断。
- 戳戳不参与普通文字合并，AI 模式不受同会话普通回复冷却拦截；原有逐用户戳戳冷却和总发送速率继续生效，也不会用戳戳去延长普通文字冷却。
- 不将通知附带的编号当作普通消息编号，避免重复检测误判。控制台新增戳戳接收、跳过原因、预设发送及失败日志。
- AI 提示中明确本轮为当前用户对机器人的戳戳互动。已有自主聊天等待流程仍可接收该互动，不额外创建重复回复。

仍需开启自动回复和“戳戳与互动 → 戳戳回复”，群聊／私聊范围必须允许。未修改用户当前开关、白名单、黑名单或登录状态。

验证：`test/qq-poke.test.ts` 新增 12 项服务级回归，覆盖两个模式、两种会话、NapCat 发起人映射、独立冷却、并发重复通知、范围限制、无效和自身事件、消息编号以及文本伪造。与 extras、bot、service、chat-rhythms、companion 共 107 项测试通过。发送接口与模型均为模拟，不向真实联系人发送测试内容。

字段来源：[NapCat 戳戳事件源码](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/event/notice/OB11PokeEvent.ts)、[NapCat 事件字段文档](https://doc.napneko.icu/onebot/basic_event)。
